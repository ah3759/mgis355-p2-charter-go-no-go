## Part A: paste into `.github/copilot-instructions.md`

### Project context

This repo is a university project (MGIS 355, Project 2): a predictive model deployed in a Streamlit app, with an honest account of how far to trust it. The data is **synthetic**, generated by `generate_data.py` (seeded, so it gives the same file every run). Every page of the app and every doc must say the data is synthetic and that the model shows the pipeline works, not that real fish behave this way.

### Fixed decisions (do not change these, and do not "improve" them)

- **Decision and user:** A Carolinas charter captain decides the evening before each booked trip whether to run it as planned or offer the client a reschedule.
- **Grain:** One row per booked charter trip, either inshore (4 hours) or offshore (8 hours, May to October only).
- **Target:** `productive` (1 or 0). Classification. It is 1 if keepers per angler were at least 2 on an inshore trip or at least 4 on an offshore trip.
- **Data:** `data/fishing_trips.csv`, 1,896 rows, 18 columns, simulated seasons 1 to 3 (2022 to 2024). Base rate of `productive` is 0.629.
- **Columns:** trip_id, trip_date, season, month, trip_type, trip_hours, species_targeted, party_size, tide_stage_start, moon_phase, days_since_front, fcst_wind_mph, fcst_wave_height_ft, fcst_air_temp_f, water_temp_f, trailing_3day_catch_rate, bites_logged_during_trip, productive.
- **Features (13, all known the evening before):** trip_type, trip_hours, month, species_targeted, party_size, tide_stage_start, moon_phase, days_since_front, fcst_wind_mph, fcst_wave_height_ft, fcst_air_temp_f, water_temp_f, trailing_3day_catch_rate.
- **Excluded on purpose:** `bites_logged_during_trip` (only exists after the trip, so it is leakage), `trip_id` (an identifier). `trip_date` and `season` are used only to split the data.
- **Split:** Time split. Train on `season` 1 and 2 (1,274 rows). Test on `season` 3 (622 rows). The test set is touched once, for the final report.
- **Baselines (fit first):** (1) majority class from the training seasons, (2) month rule: predict productive if that month's hit rate in the training seasons is above 0.5.
- **Models:** logistic regression (the simple model) and gradient boosting (`GradientBoostingClassifier`, the complex model). The complex model has to beat the simple one to be used. If it does not, say so and use the simple one.
- **Positive class** is `productive = 1`. The action is "run as planned" if the predicted probability is at or above the threshold, otherwise "offer a reschedule".
- **Costs (my decisions):**
  - `COST_RUN_UNPRODUCTIVE` = YOUR NUMBER (dollars): the captain runs a trip that fails (false positive).
  - `COST_RESCHEDULE_PRODUCTIVE` = YOUR NUMBER (dollars): the captain offers a reschedule on a trip that would have been productive (false negative).
  - Threshold = `COST_RUN_UNPRODUCTIVE / (COST_RUN_UNPRODUCTIVE + COST_RESCHEDULE_PRODUCTIVE)`, computed in the notebook, never typed in by hand.

### Hard rules (these are the mistakes agents commonly make on this assignment)

1. Never use `bites_logged_during_trip`, `trip_id`, `trip_date` or `season` as model features.
2. Fit every encoder, scaler and imputer **inside a scikit-learn Pipeline fit on the training seasons only**. Never fit anything on all rows before splitting.
3. Never tune, select or peek using the test season. Use only seasons 1 and 2 for any model selection (for example, train on season 1 and validate on season 2). Evaluate on season 3 once.
4. Never report accuracy alone. Always put the baselines next to the model, and report AUC and expected cost per trip in dollars as well. The base rate is about 0.63, so accuracy is easy to inflate.
5. The Streamlit app must **not train or fit anything**. It loads `model.joblib` with `@st.cache_resource`. Training happens only in `model.ipynb`.
6. The app must never display `nan`. Guard every formatted number.
7. Never hard-code a number in the docs. Every number in `model_card.md`, `verification.md` and the app must come from a notebook cell or from `model_meta.json`.
8. Do not invent results, sources or citations. If a number is not computed or provided, leave a clearly marked `TODO` instead.
9. Do not write `disclosure.md` beyond an empty template. It must be in my words.
10. Keep it simple. No extra models, dashboards of every column, clustering, or LLM features. Extra scope earns no credit.

### Style rules

- The notebook is organized as: load, check, split, fit, evaluate. **One step per cell, with a markdown cell above each code cell** saying in one sentence what the step is for.
- Set `random_state=355` everywhere. Use relative paths only. The notebook must run top to bottom on a clean machine and give identical numbers twice.
- Pin exact package versions in `requirements.txt` (copy them from `pip freeze` in the environment that trained the model, because the scikit-learn version must match when the app loads `model.joblib`).
